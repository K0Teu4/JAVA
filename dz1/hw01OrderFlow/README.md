## 1. Задача 1 — новый экспресс-тариф без проверки конкретного типа

Добавлен класс `domain.SameDayDelivery`:

- стоимость — **900 руб.** вне зависимости от суммы товаров;
- срок доставки — **0 дней**;
- тариф считается экспресс-доставкой;
- уведомление о создании заказа содержит текст: `Экспресс-доставка: привезём сегодня.`.

Существующий `ExpressDelivery` продолжает стоить 500 руб., доставляет на следующий день и сообщает: `Экспресс-доставка: привезём завтра.`.

### Архитектурное решение

Знание о том, относится ли тариф к экспресс-доставке, принадлежит самому тарифу и предоставляется через контракт `DeliveryTariff`:

- `express()` возвращает признак экспресс-тарифа;
- `placementMessage()` возвращает дополнительный текст для уведомления о создании заказа;
- остальные тарифы используют значения по умолчанию: не экспресс и без специального обещания.

Поэтому `SalesReport` и `ConsoleNotifier` не проверяют конкретные реализации тарифов через `instanceof`, `switch` или импорты классов тарифов. Добавление ещё одного экспресс-тарифа не требует изменения этих клиентов: достаточно реализовать контракт в новом классе тарифа.

## 2. Задача 2А — PaidOnlySalesReport

Реализован `app.PaidOnlySalesReport` с конструктором:

```java
public PaidOnlySalesReport(OrderRepository orders)
```

В отчёт попадают только заказы, для которых `order.status().paid()` возвращает `true`. В частности, оплачиваемыми считаются статусы `PAID`, `SHIPPED` и `DELIVERED`.

Пример формата:

```text
ORD-1  PAID      65490.00 руб.
ORD-3  SHIPPED   700.00 руб.
Оплаченных заказов: 2, экспресс: 1, выручка: 66190.00 руб., крупнейший: ORD-1
```

Фильтрация выполняется до формирования отчёта, поэтому она одинаково применяется ко всем данным:

- строкам заказов;
- количеству заказов;
- количеству экспресс-заказов;
- выручке;
- поиску крупнейшего заказа.

Для пустого хранилища формируется строка:

```text
Оплаченных заказов: 0, экспресс: 0, выручка: 0.00 руб., крупнейший: —
```

### Расширение SalesReport

Алгоритм `SalesReport.render()` остаётся `final`. Для выбора набора заказов добавлен hook `selectedOrders()`, который по умолчанию возвращает все заказы. `PaidOnlySalesReport` переопределяет только этот hook и шаги форматирования строк/итогов.

`TextSalesReport` и `CsvSalesReport` продолжают получать полный список заказов и сохраняют прежнее поведение.

## 3. Задача 2Б — DELIVERED

Добавлен новый статус заказа `DELIVERED` и публичный метод:

```java
order.deliver();
```

Разрешён только переход:

```text
NEW → PAID → SHIPPED → DELIVERED
```

Из любого статуса, кроме `SHIPPED`, вызов `deliver()` завершается с `IllegalStateException`. После перехода в `DELIVERED` статус терминальный: повторное вручение, оплата, отправка и отмена запрещены.

Вручённый заказ считается оплаченным: `OrderStatus.DELIVERED.paid()` возвращает `true`. Поэтому он учитывается в выручке общих и специализированных отчётов.

При запрещённом переходе исключение выбрасывается до изменения статуса.

## 4. Структура решения

Исходный код находится в `src/main/java/ru/csu/iit/master2026/oot/hw01orderflow/`.

| Пакет / класс | Назначение |
|---|---|
| `domain/DeliveryTariff` | Контракт стратегии доставки и её дополнительные свойства |
| `domain/SameDayDelivery` | Экспресс-доставка в день заказа |
| `domain/ExpressDelivery` | Экспресс-доставка на следующий день |
| `domain/OrderStatus` | Допустимые переходы между статусами |
| `domain/Order` | Сущность заказа и метод `deliver()` |
| `app/SalesReport` | Общий шаблон отчёта и hook выборки |
| `app/PaidOnlySalesReport` | Отчёт только по оплаченным заказам |
| `infra/ConsoleNotifier` | Формирование уведомлений без знания конкретных тарифов |

## 5. Запуск и тесты

Требуется **Java 21** и **Maven**.

Из корня репозитория:

```bash
mvn --batch-mode --no-transfer-progress -f dz1/pom.xml -pl hw01OrderFlow -am test
```

Запустить тесты обоих модулей:

```bash
mvn --batch-mode --no-transfer-progress -f dz1/pom.xml clean test
```

Тесты модуля проверяют исходные сценарии заказов, value objects, денежные вычисления, тарифы, статусы, точный формат текстового/CSV-отчёта и требования варианта 6.
