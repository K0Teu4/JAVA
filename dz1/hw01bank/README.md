## 1. Модель суммы и счёта

### Amount

`Amount` — неизменяемый значимый объект (value object), который хранит денежную сумму в копейках.

- Отрицательная сумма запрещена.
- `Amount.rubles(long)` создаёт значение из целого количества рублей.
- `plus` и `minus` возвращают новые значения; вычитание, приводящее к отрицательной сумме, запрещено.
- `equals` и `hashCode` основаны на количестве копеек.
- `toString()` выводит сумму в формате `1234.05 руб.`.

### Account

`Account` — сущность (entity), идентичность которой определяется только `AccountId`; баланс при этом изменяем.

Для создания доступны две фабрики:

```java
Account.debit(id);
Account.credit(id, limit);
```

Правила счетов:

| Тип | Ограничение баланса |
|---|---|
| Дебетовый | Баланс не может быть меньше 0 |
| Кредитный | Баланс не может быть меньше `-limit` |

Метод `available()` возвращает сумму, которую можно снять в данный момент. При попытке снять больше доступного остатка выбрасывается `IllegalStateException`; баланс не меняется.

Пополнение и снятие используют суммы `Amount`, чтобы операции не работали с дробными значениями рублей.

## 2. Команды банковских операций

Каждая операция реализует интерфейс `Command` с методами `execute()` и `undo()`. Команда хранит необходимые данные и состояние выполнения, поэтому может выполнить собственную компенсацию.

### Deposit

`Deposit` пополняет счёт. Отмена снимает внесённую сумму. Если внесённых средств уже недостаточно, отмена завершается с `IllegalStateException`; баланс не меняется.

### Withdraw

`Withdraw` снимает сумму в пределах `available()`. Отмена возвращает снятые средства на счёт.

### Transfer

`Transfer` переводит средства с одного счёта на другой. Перевод на тот же счёт (по идентичности `AccountId`) запрещён в конструкторе через `IllegalArgumentException`.

Выполнение и отмена построены по принципу компенсации:

1. сначала выполняется первая часть операции;
2. затем выполняется вторая часть;
3. если вторая часть выбрасывает исключение, первая часть компенсируется обратным действием;
4. флаг выполненного состояния изменяется только после успешного завершения обеих частей.

Таким образом, при штатном отказе второй части перевода состояние обоих счетов остаётся прежним.

## 3. Журнал операций

`Ledger` хранит историю выполненных команд в стеке (LIFO).

- `run(command)` выполняет команду и добавляет её в журнал только после успешного `execute()`.
- Если выполнение завершается исключением, команда не попадает в журнал.
- `undoLast()` отменяет последнюю команду и удаляет её только после успешного `undo()`.
- Если отмена завершается исключением, команда остаётся в журнале.
- `size()` возвращает количество команд, доступных для отмены.
- Вызов `undoLast()` при пустом журнале завершается с `IllegalStateException`.

## 4. Структура решения

Исходный код находится в `src/main/java/ru/csu/iit/master2026/oot/hw01bank/`.

| Класс | Назначение |
|---|---|
| `Amount` | Value object денежной суммы |
| `AccountId` | Идентификатор счёта |
| `Account` | Дебетовый/кредитный счёт и контроль баланса |
| `Command` | Контракт команды с выполнением и отменой |
| `Deposit` | Пополнение и его отмена |
| `Withdraw` | Снятие и его отмена |
| `Transfer` | Атомарный перевод и обратная операция |
| `Ledger` | Журнал выполненных команд |

## 5. Запуск и тесты

Требуется **Java 21** и **Maven**.

Из корня репозитория:

```bash
mvn --batch-mode --no-transfer-progress -f dz1/pom.xml -pl hw01bank -am test
```

Запустить тесты обоих модулей:

```bash
mvn --batch-mode --no-transfer-progress -f dz1/pom.xml clean test
```

Тесты проверяют ограничения дебетового и кредитного счетов, равенство объектов, корректность команд, LIFO-отмену, отказ операций при недостатке средств и атомарность перевода/его отмены.
